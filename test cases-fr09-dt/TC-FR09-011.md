# Apply Coupon With Invalid JWT Token - Authentication Negative Path

## ID
TC-FR09-011

## Mô tả
Kiểm tra từ chối áp dụng mã giảm giá khi JWT token không hợp lệ. Spec yêu cầu "Người dùng phải có JWT Token hợp lệ" (C4). Token có thể:
- Bị hỏng (malformed)
- Đã hết hạn (expired)
- Chữ ký không khớp
- Không được ký bởi hệ thống

Mặc dù mã hợp lệ, đơn hàng đủ tiền, nhưng token không thể xác thực. Hệ thống phải từ chối.

## Môi trường kiểm thử
- OS: Windows 10 / macOS Monterey / Ubuntu 20.04
- Browser: Google Chrome Version 120+, Firefox 121+
- Backend: Node.js 18+ LTS
- Database: MySQL 8.0+ / PostgreSQL 14+
- API Environment: Staging / Production

## Precondition
1. Database có mã SAVE10 và các mã hợp lệ khác

2. Người dùng sẽ gửi request với JWT token **không hợp lệ**. Có các kịch bản:
   - Token đã hết hạn (exp < ngày hiện tại)
   - Token bị hỏng (malformed, không phải JWT format)
   - Token có chữ ký sai
   - Token không được ký bởi hệ thống

3. Các tokens để test:
   - Expired: `eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJleHAiOjE2MjI1NDc2MDB9.[signature]` (exp = 2021)
   - Malformed: `notavalidtoken123`
   - Wrong signature: `eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.[payload].[wrongsignature]`

4. Đơn hàng có tổng tiền = 500,000 ₫ (đủ tiền)

## Các điều kiện

- C1: Mã tồn tại - **Exists_Active** (SAVE10 tồn tại và hoạt động)
- C2: Còn hạn sử dụng - **Not_Expired** (expired_at = 2099-12-31, sau ngày hiện tại)
- C3: Đủ ngưỡng đơn hàng - **Above_Threshold** (500,000 >= 300,000)
- C4: Đã đăng nhập - **Invalid_Token** (token không hợp lệ)
- C5: Chưa dùng hết lượt - **Within_Limit** (giả định nếu được xác thực)

## Các bước thực hiện

### Scenario A: Expired Token
1. Người dùng có token đã hết hạn (exp < ngày hiện tại)
2. Điều hướng tới trang Checkout
3. Nhập mã giảm giá "SAVE10" vào trường input
4. Click nút "Áp dụng mã giảm giá"
5. Hệ thống xử lý yêu cầu với Authorization header chứa expired token

### Scenario B: Malformed Token
1. Người dùng (hoặc attacker) gửi token không phải JWT format
2. Request coupon application với header Authorization: `Bearer notavalidtoken123`
3. Hệ thống xử lý yêu cầu

### Scenario C: Wrong Signature
1. Token được tạo bằng secret key khác
2. Hệ thống không thể verify chữ ký
3. Request coupon application
4. Hệ thống xử lý

## Kết quả mong đợi

1. **Response status**: 401 Unauthorized
2. **API Response body**:
   ```json
   {
     "success": false,
     "error_code": "INVALID_TOKEN",
     "message": "JWT Token không hợp lệ hoặc đã hết hạn"
   }
   ```
   Hoặc chi tiết hơn:
   ```json
   {
     "success": false,
     "error_code": "TOKEN_EXPIRED",
     "message": "Phiên đăng nhập đã hết hạn. Vui lòng đăng nhập lại"
   }
   ```
   Hoặc:
   ```json
   {
     "success": false,
     "error_code": "TOKEN_INVALID",
     "message": "Token không hợp lệ. Vui lòng đăng nhập lại"
   }
   ```

3. **UI Updates**:
   - Trường mã giảm giá không bị khóa
   - Hiển thị thông báo lỗi (màu đỏ): "Phiên đăng nhập không hợp lệ. Vui lòng đăng nhập lại"
   - Có thể tự động redirect tới trang login
   - Hoặc hiển thị nút "Đăng nhập lại"
   - Tổng tiền vẫn giữ nguyên, không áp dụng giảm giá

4. **Database verification**:
   - Bảng coupon_usage không có record mới
   - Không có audit log cho action này

5. **Log verification**:
   - Server logs ghi nhận:
     - `[WARN] Coupon request rejected: reason=INVALID_TOKEN, token_status=expired`
     - `[WARN] Coupon request rejected: reason=INVALID_TOKEN, token_status=malformed`
     - `[WARN] Coupon request rejected: reason=INVALID_TOKEN, token_status=wrong_signature`
