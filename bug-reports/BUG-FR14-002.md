# BUG-FR14-002: PUT/DELETE operations succeed on non-existent category IDs (Missing Resource Validation)

**Severity:** Medium  
**Category:** API Contract / Error Handling  
**Status:** Open  
**Date:** 2026-08-20  
**Student ID:** 23127300  

---

## Summary

Update and delete operations on non-existent category IDs return `200 OK` instead of `404 Not Found`. The API does not validate resource existence before reporting success.

---

## Affected Endpoints

- `PUT /api/categories/:id`
- `DELETE /api/categories/:id`

---

## Expected Behavior (per REST Standards)

When attempting to modify or delete a non-existent resource, the API should return `404 Not Found`:

```http
HTTP/1.1 404 Not Found
Content-Type: application/json

{
  "error": "Category not found"
}
```

This is standard RESTful behavior for resource-not-found scenarios.

---

## Actual Behavior

Operations on non-existent category IDs return success responses.

## Root Cause (Inferred from Behavior)

The backend likely executes raw SQL `UPDATE`/`DELETE` statements without checking `affectedRows`:

```javascript
// Vulnerable implementation (inferred)
async updateCategory(id, name) {
  const result = await db.run('UPDATE categories SET name = ? WHERE id = ?', [name, id]);
  // Bug: does not check result.changes
  return { message: 'Category updated' };
}

async deleteCategory(id) {
  const result = await db.run('DELETE FROM categories WHERE id = ?', [id]);
  // Bug: does not check result.changes
  return { message: 'Category deleted' };
}
```

SQLite (and most databases) return success even when `WHERE` clauses match zero rows. The application must explicitly check `result.changes` or `affectedRows`.

---

## Recommended Fix

1. Check affected row count after UPDATE/DELETE operations
2. Return `404 Not Found` when zero rows affected
3. Example fix:

```javascript
async updateCategory(id, name) {
  const result = await db.run('UPDATE categories SET name = ? WHERE id = ?', [name, id]);
  if (result.changes === 0) {
    throw new NotFoundError('Category not found');
  }
  return { message: 'Category updated' };
}
```

4. Add tests verifying 404 responses for non-existent IDs
