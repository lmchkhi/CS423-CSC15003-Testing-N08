# [BUG][FR-14 Category CRUD] PUT/DELETE operations succeed on non-existent category IDs

## Found by Test Case
TC-FR14-026, TC-FR14-043 và TC-FR14-044 — kiểm thử ID không tồn tại phát hiện SUT báo thành công dù không có tài nguyên được cập nhật hoặc xóa.

## Requirement liên quan
FR-14 Category CRUD: Khi sửa hoặc xóa danh mục theo `id`, hệ thống phải kiểm tra danh mục có tồn tại hay không. Nếu `id` không tồn tại, API phải trả `404 Not Found`.

## Severity / Priority
Medium / P2

## Environment
**Tool**: Postman collection v2.1 / Newman headless
**Collection**: `api/collections/eshop-hw06.postman_collection.json`
**Environment file**: `api/environments/local.postman_environment.json` (`baseUrl = http://localhost:3000`)
**Observed request host**: `http://127.0.0.1:3000` trong collection/Newman logs
**Folder / report**: `FR-14 Lifecycle & Access`, `api/newman/fr14-lifecycle-report.html`
**Endpoints involved**: `PUT /api/categories/:id`, `DELETE /api/categories/:id`
**Anti-cheat header**: `X-Student-Id: 23127300`
**OS / Hardware / build**: Không được ghi nhận trong Newman artifact nộp; không dùng làm bằng chứng cho bug này.

## Steps to reproduce
1. Đăng nhập bằng tài khoản admin và lấy JWT token.
2. Gọi `GET /api/categories` để xác nhận không có danh mục với ID `999999`.
3. Gửi `PUT /api/categories/999999` với body `{"name":"Ghost Update"}`.
4. Quan sát hệ thống trả `200 OK`.
5. Gửi `DELETE /api/categories/999999`.
6. Quan sát hệ thống tiếp tục trả `200 OK`.

## Expected result
Khi ID danh mục không tồn tại, cả `PUT` và `DELETE` phải trả `404 Not Found`, ví dụ:

```json
{
  "error": "Category not found"
}
```

## Actual result
SUT trả phản hồi thành công dù không có danh mục nào được cập nhật hoặc xóa. Client không thể phân biệt thao tác thật sự thành công với thao tác không có tác dụng.

## Evidence
**Yêu cầu PUT danh mục không tồn tại:**

```http
PUT /api/categories/999999 HTTP/1.1
Host: 127.0.0.1:3000
Content-Type: application/json
Authorization: Bearer <admin_token>
X-Student-Id: 23127300

{
  "name": "Ghost Update"
}
```

**Actual Response:**

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "Category updated"
}
```

**Yêu cầu DELETE danh mục không tồn tại:**

```http
DELETE /api/categories/999999 HTTP/1.1
Host: 127.0.0.1:3000
Authorization: Bearer <admin_token>
X-Student-Id: 23127300
```

**Actual Response:**

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "Category deleted"
}
```

Kết quả Newman:
- `TC-FR14-026`: `PUT` ID không tồn tại trả `200`, trong khi mong đợi `404`.
- `TC-FR14-044`: `DELETE` ID không tồn tại trả `200`, trong khi mong đợi `404`.
- `TC-FR14-023` và `TC-FR14-030`: thao tác với ID tồn tại trả `200`, đúng kỳ vọng.

## Impact
Lỗi này không gây mất dữ liệu trực tiếp, nhưng làm sai hợp đồng API. Frontend hoặc client có thể hiển thị "cập nhật thành công" cho dữ liệu không tồn tại, gây khó debug và làm người dùng tin nhầm rằng thao tác đã có hiệu lực.

## Root Cause
Suy luận từ hành vi: backend có thể chạy câu lệnh `UPDATE` hoặc `DELETE` nhưng không kiểm tra số dòng bị ảnh hưởng.

```javascript
async updateCategory(id, name) {
  const result = await db.run('UPDATE categories SET name = ? WHERE id = ?', [name, id]);
  // Bug: chưa kiểm tra result.changes
  return { message: 'Category updated' };
}
```

SQLite vẫn xem câu lệnh là chạy thành công dù `WHERE` không khớp dòng nào. Ứng dụng cần tự kiểm tra `result.changes` hoặc `affectedRows`.

## Recommended Fix
1. Sau `UPDATE`/`DELETE`, kiểm tra số dòng bị ảnh hưởng.
2. Nếu bằng 0, trả `404 Not Found`.
3. Bổ sung test cho cả `PUT` và `DELETE` với ID không tồn tại.
