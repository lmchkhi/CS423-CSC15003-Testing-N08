# [BUG][FR-14 Category CRUD] Empty and whitespace-only category names accepted

## Found by Test Case
TC-FR14-003, TC-FR14-005, TC-FR14-046 và TC-FR14-047 — kiểm thử dữ liệu đầu vào phát hiện tên danh mục rỗng hoặc chỉ có khoảng trắng vẫn được tạo.

## Requirement liên quan
FR-14 Category CRUD: Tên danh mục phải có nội dung có nghĩa sau khi loại bỏ khoảng trắng đầu/cuối. Chuỗi rỗng hoặc chỉ gồm khoảng trắng phải bị từ chối.

## Severity / Priority
Medium / P2

## Environment
**Tool**: Postman collection v2.1 / Newman headless
**Collection**: `api/collections/eshop-hw06.postman_collection.json`
**Environment file**: `api/environments/local.postman_environment.json` (`baseUrl = http://localhost:3000`)
**Observed request host**: `http://127.0.0.1:3000` trong collection/Newman logs
**Folder / data / report**: `FR-14 Category CRUD`, `api/data/fr14-post-categories.csv`, `api/newman/fr14-category-report.html`
**Endpoint involved**: `POST /api/categories`
**Anti-cheat header**: `X-Student-Id: 23127300`
**OS / Hardware / build**: Không được ghi nhận trong Newman artifact nộp; không dùng làm bằng chứng cho bug này.

## Steps to reproduce
1. Đăng nhập bằng tài khoản admin và lấy JWT token.
2. Gửi `POST /api/categories` với `{"name":""}`.
3. Quan sát hệ thống trả `200 OK` và tạo danh mục mới.
4. Gửi `POST /api/categories` với `{"name":"   "}`.
5. Quan sát hệ thống tiếp tục trả `200 OK`.
6. Gọi `GET /api/categories` để xác nhận có danh mục tên rỗng hoặc chỉ gồm khoảng trắng.

## Expected result
Tên danh mục rỗng hoặc chỉ gồm khoảng trắng phải bị từ chối với `400 Bad Request`, ví dụ:

```json
{
  "error": "Category name is required and cannot be empty"
}
```

## Actual result
SUT chấp nhận cả chuỗi rỗng và chuỗi chỉ gồm khoảng trắng làm tên danh mục. Các danh mục này có thể hiển thị như dòng trống trong dropdown, menu hoặc màn hình quản trị.

## Evidence
**Yêu cầu tạo danh mục tên rỗng:**

```http
POST /api/categories HTTP/1.1
Host: 127.0.0.1:3000
Content-Type: application/json
Authorization: Bearer <admin_token>
X-Student-Id: 23127300

{
  "name": ""
}
```

**Actual Response:**

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "Category created",
  "id": 23
}
```

**Yêu cầu tạo danh mục chỉ có khoảng trắng:**

```http
POST /api/categories HTTP/1.1
Host: 127.0.0.1:3000
Content-Type: application/json
Authorization: Bearer <admin_token>
X-Student-Id: 23127300

{
  "name": "   "
}
```

**Actual Response:**

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "Category created",
  "id": 24
}
```

**Kiểm chứng bằng `GET /api/categories`:**

```json
[
  {"id": 23, "name": ""},
  {"id": 24, "name": "   "}
]
```

Kết quả Newman:
- `TC-FR14-003`: POST tên rỗng mong đợi `400`, nhưng nhận `200`.
- `TC-FR14-005`: POST tên chỉ có khoảng trắng mong đợi `400`, nhưng nhận `200`.
- `TC-FR14-046` và `TC-FR14-047`: test bổ sung của sinh viên xác nhận lại cùng lỗi.

## Impact
Lỗi này tạo dữ liệu danh mục không có ý nghĩa, gây dòng trống trong UI và làm người dùng khó chọn đúng danh mục. Đây là lỗi chất lượng dữ liệu và kiểm tra dữ liệu đầu vào, không phải lỗi crash hay bảo mật, nên mức độ phù hợp là Medium.

## Recommended Fix
1. Trim `name` trước khi validate và lưu database.
2. Trả `400 Bad Request` nếu `name` sau khi trim là chuỗi rỗng.
3. Đặt giới hạn độ dài hợp lý cho tên danh mục.
4. Bổ sung test cho chuỗi rỗng, chuỗi chỉ có khoảng trắng và chuỗi có khoảng trắng đầu/cuối.
