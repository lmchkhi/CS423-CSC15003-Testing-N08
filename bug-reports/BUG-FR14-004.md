# BUG-FR14-004: Empty and whitespace-only category names accepted (Missing Input Validation)

**Severity:** Medium  
**Category:** Input Validation / Data Quality  
**Status:** Open  
**Date:** 2026-08-20  
**Student ID:** 23127300  

---

## Summary

The API accepts empty strings and whitespace-only strings as valid category names, creating semantically invalid categories that break UI rendering and user experience.

---

## Affected Endpoints

- `POST /api/categories`

---

## Expected Behavior (per Input Validation Best Practices)

Category names should be validated for meaningful content. Empty or whitespace-only names should be rejected:

```http
HTTP/1.1 400 Bad Request
Content-Type: application/json

{
  "error": "Category name is required and cannot be empty"
}
```

---

## Actual Behavior

Empty strings and whitespace-only strings are accepted as valid category names.

### Test Case: TC-FR14-046 (Empty string)

**Request:**
```http
POST /api/categories HTTP/1.1
Host: 127.0.0.1:3000
Content-Type: application/json
Authorization: Bearer <admin_token>
X-Student-Id: 23127300

{
  "name": ""
}
```

**Actual Response:**
```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "Category created",
  "id": 23
}
```

**Expected:** `400 Bad Request`

---

### Test Case: TC-FR14-047 (Whitespace-only)

**Request:**
```http
POST /api/categories HTTP/1.1
Host: 127.0.0.1:3000
Content-Type: application/json
Authorization: Bearer <admin_token>
X-Student-Id: 23127300

{
  "name": "   "
}
```

**Actual Response:**
```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "Category created",
  "id": 24
}
```

**Expected:** `400 Bad Request`

**Verification:** `GET /api/categories` returns:
```json
[
  {"id": 23, "name": ""},
  {"id": 24, "name": "   "}
]
```

These categories render as blank labels in UI dropdowns.

## Root Cause (Inferred from Behavior)

The Express.js application lacks input validation middleware. Raw inputs are passed directly to the database:

```javascript
// Vulnerable implementation (inferred)
router.post('/categories', authenticateToken, async (req, res) => {
  const { name } = req.body;
  // Bug: no validation on name
  const result = await db.run('INSERT INTO categories (name) VALUES (?)', [name]);
  res.json({ message: 'Category created', id: result.lastID });
});
```

No validation library (e.g., Joi, express-validator) is applied, and JavaScript accepts empty strings as truthy enough to pass `if (name)` checks.

---

## Recommended Fix

1. **Add validation middleware** (e.g., express-validator):
   ```javascript
   const { body, validationResult } = require('express-validator');
   
   router.post('/categories',
     authenticateToken,
     body('name')
       .trim()
       .notEmpty().withMessage('Category name is required')
       .isLength({ min: 1, max: 255 }).withMessage('Name must be 1-255 characters'),
     async (req, res) => {
       const errors = validationResult(req);
       if (!errors.isEmpty()) {
         return res.status(400).json({ error: errors.array()[0].msg });
       }
       // Proceed with sanitized name
     }
   );
   ```

2. **Manual validation** (if middleware unavailable):
   ```javascript
   const name = req.body.name?.trim();
   if (!name || name.length === 0) {
     return res.status(400).json({ error: 'Category name is required' });
   }
   ```

3. Add tests verifying rejection of empty/whitespace inputs
