# [BUG][FR-14 Category CRUD] Non-admin users can create and delete categories

## Found by Test Case
TC-FR14-041, TC-FR14-042 và TC-FR14-033 — kiểm thử phân quyền phát hiện user không phải admin vẫn thực hiện được thao tác CRUD danh mục.

## Requirement liên quan
FR-14 Category CRUD / Admin Operations: Các thao tác tạo, sửa, xóa danh mục phải yêu cầu tài khoản admin. User thường chỉ được đọc danh sách danh mục.

## Severity / Priority
Critical / P0

## Environment
**Tool**: Postman collection v2.1 / Newman headless
**Collection**: `api/collections/eshop-hw06.postman_collection.json`
**Environment file**: `api/environments/local.postman_environment.json` (`baseUrl = http://localhost:3000`)
**Observed request host**: `http://127.0.0.1:3000` trong collection/Newman logs
**Folder / report**: `FR-14 Lifecycle & Access`, `api/newman/fr14-lifecycle-report.html`
**Endpoints involved**: `POST /api/categories`, `DELETE /api/categories/:id`
**Anti-cheat header**: `X-Student-Id: 23127300`
**OS / Hardware / build**: Không được ghi nhận trong Newman artifact nộp; không dùng làm bằng chứng cho bug này.

## Steps to reproduce
1. Đăng ký hoặc đăng nhập bằng tài khoản user thường.
2. Lấy JWT token của user thường.
3. Gửi `POST /api/categories` với header `Authorization: Bearer <user_token>` và body `{"name":"Escalated Category"}`.
4. Quan sát hệ thống trả `200 OK` và tạo danh mục mới.
5. Gửi `DELETE /api/categories/<id>` với cùng token user thường.
6. Quan sát hệ thống tiếp tục trả `200 OK` và xóa danh mục.

## Expected result
Các yêu cầu tạo, sửa hoặc xóa danh mục bằng token của user thường phải bị từ chối với `403 Forbidden`, ví dụ:

```json
{
  "error": "Forbidden: Admin access required"
}
```

## Actual result
User thường có JWT hợp lệ vẫn tạo và xóa danh mục thành công. SUT có kiểm tra người dùng đã đăng nhập hay chưa, nhưng không kiểm tra role admin trước khi cho phép thao tác.

## Evidence
**Yêu cầu tạo danh mục bằng user thường:**

```http
POST /api/categories HTTP/1.1
Host: 127.0.0.1:3000
Content-Type: application/json
Authorization: Bearer <user_token>
X-Student-Id: 23127300

{
  "name": "Escalated Category"
}
```

**Actual Response:**

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "Category created",
  "id": 5
}
```

**Yêu cầu xóa danh mục bằng user thường:**

```http
DELETE /api/categories/5 HTTP/1.1
Host: 127.0.0.1:3000
Authorization: Bearer <user_token>
X-Student-Id: 23127300
```

**Actual Response:**

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "Category deleted"
}
```

Kết quả Newman:
- `TC-FR14-041`: User thường gửi POST trả `200`, trong khi mong đợi `403`.
- `TC-FR14-042`: User thường gửi DELETE trả `200`, trong khi mong đợi `403`.
- `TC-FR14-014`: Request không đăng nhập bị từ chối `401`, nghĩa là SUT có kiểm tra token nhưng thiếu kiểm tra role.

## Impact
Đây là lỗi phân quyền nghiêm trọng. Bất kỳ user đã đăng ký nào cũng có thể thay đổi hệ thống phân loại danh mục, xóa danh mục hợp lệ hoặc tạo danh mục rác. Điều này làm hỏng dữ liệu điều hướng sản phẩm, phá vỡ logic quản trị và là dấu hiệu của kiểm soát truy cập bị lỗi.

## Recommended Fix
1. Thêm middleware kiểm tra role admin, ví dụ `isAdmin`.
2. Áp dụng cho toàn bộ endpoint admin-only của danh mục: `POST`, `PUT`, `DELETE`.
3. Trả `403 Forbidden` khi `req.user.role !== 'admin'`.
4. Bổ sung test tích hợp cho user thường, user chưa đăng nhập và admin.
