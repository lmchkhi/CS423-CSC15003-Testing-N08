# BUG-FR14-001: Non-admin users can create and delete categories (Broken Access Control)

**Severity:** Critical  
**Category:** Security / Access Control (OWASP A01:2021)  
**Status:** Open  
**Date:** 2026-08-20  
**Student ID:** 23127300  

---

## Summary

Regular authenticated users can perform admin-only operations (create/delete categories) without role verification. The API validates JWT token existence but does not check user roles.

---

## Affected Endpoints

- `POST /api/categories`
- `PUT /api/categories/:id`
- `DELETE /api/categories/:id`

---

## Expected Behavior (per Specification)

API Specification §3.3 "Admin Operations" states:
> "Category CRUD operations require admin authentication."

Expected response when non-admin user attempts admin operation:
```
HTTP/1.1 403 Forbidden
Content-Type: application/json

{
  "error": "Forbidden: Admin access required"
}
```

---

## Actual Behavior

Non-admin users with valid JWT tokens can successfully create and delete categories.

### Test Case: TC-FR14-041 (Non-admin creates category)

**Request:**
```http
POST /api/categories HTTP/1.1
Host: 127.0.0.1:3000
Content-Type: application/json
Authorization: Bearer <user_token>
X-Student-Id: 23127300

{
  "name": "Escalated Category"
}
```

**Actual Response:**
```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "Category created",
  "id": 5
}
```

**Expected:** `403 Forbidden` with error message

---

### Test Case: TC-FR14-042 (Non-admin deletes category)

**Request:**
```http
DELETE /api/categories/5 HTTP/1.1
Host: 127.0.0.1:3000
Authorization: Bearer <user_token>
X-Student-Id: 23127300
```

**Actual Response:**
```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "Category deleted"
}
```

**Expected:** `403 Forbidden` with error message

---

## Reproduction Steps

1. Register regular user: `POST /api/register` with `{"name":"Regular User","email":"user@eshop.com","password":"User123!"}`
2. Login as regular user: `POST /api/login` → obtain `userToken`
3. Attempt to create category: `POST /api/categories` with `Authorization: Bearer <userToken>` and `{"name":"Test Category"}`
4. Observe: **200 OK** response with category ID (should be 403)
5. Attempt to delete category: `DELETE /api/categories/<id>` with user token
6. Observe: **200 OK** response (should be 403)

---

## Impact Assessment

**Security Risk:** **CRITICAL**

- **Data Integrity:** Unauthorized users can corrupt the category taxonomy
- **Business Logic Bypass:** Role-based access control (RBAC) is ineffective
- **Attack Vector:** Any registered user can perform privilege escalation
- **CWE Classification:** CWE-862 (Missing Authorization)

**Real-World Impact:**
- Malicious users can delete legitimate categories → breaks product navigation
- Spam categories can be injected → degrades user experience
- No audit trail distinguishes admin vs. user actions

---

## Evidence

**Newman Test Report:** `api/newman/fr14-category-report.html`

**Test Results:**
- TC-FR14-041: Non-admin POST → 200 (expected 403) ❌
- TC-FR14-042: Non-admin DELETE → 200 (expected 403) ❌
- TC-FR14-014: No auth POST → 401 (correct) ✅

The SUT correctly rejects **unauthenticated** requests but fails to enforce **role-based** access control.

---

## Root Cause (Inferred from Behavior)

The category endpoints likely use `authenticateToken` middleware (validates JWT) but lack `isAdmin` middleware (checks user role). Example vulnerable implementation:

```javascript
// Missing role check
router.post('/categories', authenticateToken, createCategory);
router.delete('/categories/:id', authenticateToken, deleteCategory);
```

Should be:
```javascript
router.post('/categories', authenticateToken, isAdmin, createCategory);
router.delete('/categories/:id', authenticateToken, isAdmin, deleteCategory);
```

---

## Recommended Fix

1. Implement role-based middleware (`isAdmin` or equivalent)
2. Apply to all admin-only endpoints in category router
3. Return `403 Forbidden` when `req.user.role !== 'admin'`
4. Add integration tests verifying role enforcement
