# BUG-FR08-002: Missing input validation for total_amount in checkout

## Found by Test Case
FR-08 Checkout API test case — boundary value analysis detecting acceptance of negative and zero amounts

## Requirement liên quan
FR-08 Checkout: total_amount phải là số dương (> 0). Hệ thống phải reject request với total_amount ≤ 0 hoặc không hợp lệ và trả về 400 Bad Request

## Severity / Priority
High / P1

## Environment
**Tool**: Postman / Newman 11.x
**OS / Hardware**: macOS 15.5, Apple Silicon M1, 8GB RAM
**SUT**: EShop backend, http://127.0.0.1:3000/api/checkout
**Student ID**: 23127300

## Steps to reproduce
1. POST /api/login với credentials hợp lệ để lấy JWT token
2. POST /api/checkout với total_amount = -5000
3. Hệ thống trả về 200 OK và tạo order thành công

## Expected result
Request với total_amount ≤ 0 phải bị từ chối với HTTP 400 Bad Request và message "total_amount must be a positive number" hoặc tương tự

## Actual result
Hệ thống chấp nhận total_amount âm, tạo order thành công với orderId mới và trả về 200 OK. Order được lưu vào database với giá trị âm.

## Evidence
```bash
# Login to get token
curl -X POST http://127.0.0.1:3000/api/login \
  -H "Content-Type: application/json" \
  -H "X-Student-Id: 23127300" \
  -d '{"email":"bugtester@test.com","password":"Pass123!"}'

Response: {"message":"Login successful","token":"eyJhbGci..."}

# Checkout with negative total_amount
curl -X POST http://127.0.0.1:3000/api/checkout \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." \
  -H "X-Student-Id: 23127300" \
  -d '{"total_amount":-5000,"shipping_address":"123 Test St"}'

Response: 200 OK
{"message":"Checkout successful","orderId":3}
```

Cho phép tạo order với total_amount âm dẫn đến:
- Dữ liệu không nhất quán trong database
- Tiềm ẩn lỗi logic trong báo cáo doanh thu, thống kê
- Có thể bị lợi dụng để gian lận hoặc làm sai lệch số liệu tài chính
