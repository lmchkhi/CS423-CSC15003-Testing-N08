## Found by Test Case

TC-FR10-DTT-007

## Requirement liên quan

FR-10 — Trạng thái Đơn hàng (Order State Machine), FR-20 (Mobile)

## Severity / Priority

Critical / P0

## Environment

- API Tool: Postman / cURL
- Browser: Chrome (latest)
- OS: Windows
- Backend: http://localhost:3000
- Frontend: http://localhost:5173
- API: PUT /api/orders/:id/cancel

## Steps to reproduce

1. Đăng nhập vào Frontend Web tại http://localhost:5173 với tài khoản test@eshop.com / Test1234!
2. Tạo đơn hàng mới (nếu chưa có đơn ở trạng thái shipping)
3. Nhờ Admin chuyển đơn hàng sang trạng thái `shipping` (pending → confirmed → shipping)
4. Quay lại tài khoản User, truy cập trang "Lịch sử đơn hàng"
5. Tìm đơn hàng có trạng thái "shipping"
6. Gọi API: `PUT /api/orders/:id/cancel` với Bearer Token của User
7. Quan sát phản hồi từ hệ thống

## Expected result

Theo đặc tả FR-10:

> "Khi đơn hàng đã ở trạng thái shipping, **User không được phép tự hủy** — chỉ Admin mới có thể thao tác."

- ❌ Hệ thống **từ chối** yêu cầu hủy đơn hàng
- API trả về HTTP 400/403 với thông báo lỗi phù hợp
- Đơn hàng **vẫn giữ nguyên** trạng thái `shipping`
- Trên giao diện: nút "Hủy đơn hàng" nên bị **ẩn hoặc disable** cho đơn hàng ở trạng thái shipping

## Actual result

- Hệ thống **hủy đơn hàng shipping thành công** — vi phạm ràng buộc State Machine
- API trả về **HTTP 200 OK** với thông tin đơn hàng đã cập nhật sang trạng thái `canceled`
- Đơn hàng bị chuyển sang `canceled` dù User không có quyền thực hiện thao tác này

## Root Cause Analysis (Giả thuyết)

API endpoint `PUT /api/orders/:id/cancel` có thể **không kiểm tra trạng thái hiện tại** của đơn hàng trước khi cho phép hủy. Code backend có thể thiếu validation logic tương tự:

```javascript
// Thiếu kiểm tra:
if (order.status === 'shipping') {
  return res.status(400).json({
    error: 'Không thể hủy đơn hàng đang giao. Vui lòng liên hệ Admin.'
  });
}
```

## Impact

- **Mức độ ảnh hưởng:** Critical — vi phạm trực tiếp business rule của State Machine
- **Phạm vi:** Tất cả đơn hàng đang ở trạng thái `shipping` có thể bị User tự ý hủy
- **Hậu quả:** 
  - Đơn hàng đang vận chuyển bị hủy không kiểm soát
  - Tổn thất logistics — hàng đã giao cho bên vận chuyển nhưng bị cancel
  - Vi phạm quy trình vận hành — Admin mất quyền kiểm soát đơn hàng đang shipping
  - Ảnh hưởng đến FR-20 (Mobile) vì cùng API endpoint
