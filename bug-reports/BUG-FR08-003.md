# BUG-FR08-003: Illegal order state transition canceled→delivered accepted

## Found by Test Case
FR-08 Checkout API test case — state machine validation detecting violation of FR-10 order status transition rules

## Requirement liên quan
FR-10 Order State Machine: Từ trạng thái "canceled", order không được phép chuyển sang bất kỳ trạng thái nào khác. "canceled" là trạng thái kết thúc (terminal state).

## Severity / Priority
High / P1

## Environment
**Tool**: Postman / Newman 11.x
**OS / Hardware**: macOS 15.5, Apple Silicon M1, 8GB RAM
**SUT**: EShop backend, http://127.0.0.1:3000/api/admin/orders/:id/status
**Student ID**: 23127300

## Steps to reproduce
1. POST /api/login với admin credentials để lấy admin JWT token
2. POST /api/checkout để tạo order mới (orderId = 4, status = "pending")
3. PUT /api/admin/orders/4/status với {"status":"canceled"} để chuyển sang canceled
4. PUT /api/admin/orders/4/status với {"status":"delivered"} để thử chuyển từ canceled→delivered
5. Hệ thống trả về 200 OK và chấp nhận transition bất hợp lệ

## Expected result
Request chuyển từ "canceled" sang "delivered" phải bị từ chối với HTTP 400 Bad Request và message "Invalid status transition from canceled to delivered" hoặc tương tự. Theo FR-10, "canceled" là terminal state, không được phép chuyển tiếp.

## Actual result
Hệ thống chấp nhận transition bất hợp lệ, trả về 200 OK với message "Order status updated". Order status trong database được cập nhật thành "delivered" mặc dù đã bị canceled trước đó.

## Evidence
```bash
# Admin login
curl -X POST http://127.0.0.1:3000/api/login \
  -H "Content-Type: application/json" \
  -H "X-Student-Id: 23127300" \
  -d '{"email":"admin@eshop.com","password":"Admin123!"}'

Response: {"message":"Login successful","token":"eyJhbGci..."}

# Create order (returns orderId: 4, status: "pending")
curl -X POST http://127.0.0.1:3000/api/checkout \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <user_token>" \
  -H "X-Student-Id: 23127300" \
  -d '{"total_amount":100000,"shipping_address":"456 Test Ave"}'

# Transition to canceled
curl -X PUT http://127.0.0.1:3000/api/admin/orders/4/status \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <admin_token>" \
  -H "X-Student-Id: 23127300" \
  -d '{"status":"canceled"}'

Response: 200 OK {"message":"Order status updated"}

# Illegal transition: canceled→delivered (should fail, but succeeds)
curl -X PUT http://127.0.0.1:3000/api/admin/orders/4/status \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <admin_token>" \
  -H "X-Student-Id: 23127300" \
  -d '{"status":"delivered"}'

Response: 200 OK {"message":"Order status updated"}
```

Vi phạm business logic của order state machine, cho phép "hồi sinh" order đã bị hủy. Điều này gây mâu thuẫn với quy trình kinh doanh, có thể dẫn đến:
- Confusion trong tracking và reporting
- Rủi ro pháp lý khi order đã hủy bỗng nhiên được đánh dấu "delivered"
- Dữ liệu không đáng tin cậy cho analytics và dashboard
