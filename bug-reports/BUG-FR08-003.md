# [BUG][FR-08 Checkout] Illegal order state transition canceled→delivered accepted

## Found by Test Case
FR-08 Checkout API test case — kiểm thử state machine phát hiện vi phạm luật chuyển trạng thái đơn hàng của FR-10

## Requirement liên quan
FR-10 Order State Machine: Từ trạng thái `canceled`, đơn hàng không được phép chuyển sang bất kỳ trạng thái nào khác. `canceled` là trạng thái kết thúc.

## Severity / Priority
High / P1

## Environment
**Tool**: Postman collection v2.1 / Newman headless
**Collection**: `api/collections/eshop-hw06.postman_collection.json`
**Environment file**: `api/environments/local.postman_environment.json` (`baseUrl = http://localhost:3000`)
**Observed request host**: `http://127.0.0.1:3000` trong collection/Newman logs
**Folder / report**: `FR-08 State & Security`, `api/newman/fr08-state-report.html`
**Endpoint involved**: `PUT /api/admin/orders/:id/status`
**Anti-cheat header**: `X-Student-Id: 23127300`
**OS / Hardware / build**: Không được ghi nhận trong Newman artifact nộp; không dùng làm bằng chứng cho bug này.

## Steps to reproduce
1. Gửi `POST /api/login` với tài khoản admin để lấy admin JWT token.
2. Gửi `POST /api/checkout` để tạo đơn hàng mới (`orderId = 4`, `status = "pending"`).
3. Gửi `PUT /api/admin/orders/4/status` với `{"status":"canceled"}` để chuyển đơn hàng sang `canceled`.
4. Gửi `PUT /api/admin/orders/4/status` với `{"status":"delivered"}` để thử chuyển từ `canceled` sang `delivered`.
5. Quan sát hệ thống trả `200 OK` và chấp nhận chuyển trạng thái bất hợp lệ.

## Expected result
Request chuyển từ `canceled` sang `delivered` phải bị từ chối với `400 Bad Request`, kèm thông báo như `"Invalid status transition from canceled to delivered"` hoặc nội dung tương đương. Theo FR-10, `canceled` là trạng thái kết thúc và không được phép chuyển tiếp.

## Actual result
Hệ thống chấp nhận chuyển trạng thái bất hợp lệ, trả `200 OK` với message `"Order status updated"`. Trạng thái đơn hàng trong database được cập nhật thành `delivered` dù đơn hàng đã bị hủy trước đó.

## Evidence
```bash
# Đăng nhập admin
curl -X POST http://127.0.0.1:3000/api/login \
  -H "Content-Type: application/json" \
  -H "X-Student-Id: 23127300" \
  -d '{"email":"admin@eshop.com","password":"Admin123!"}'

Phản hồi: {"message":"Login successful","token":"eyJhbGci..."}

# Tạo đơn hàng, nhận orderId = 4 và status = "pending"
curl -X POST http://127.0.0.1:3000/api/checkout \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <user_token>" \
  -H "X-Student-Id: 23127300" \
  -d '{"total_amount":100000,"shipping_address":"456 Test Ave"}'

# Chuyển sang canceled
curl -X PUT http://127.0.0.1:3000/api/admin/orders/4/status \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <admin_token>" \
  -H "X-Student-Id: 23127300" \
  -d '{"status":"canceled"}'

Phản hồi: 200 OK {"message":"Order status updated"}

# Chuyển trạng thái bất hợp lệ: canceled -> delivered
curl -X PUT http://127.0.0.1:3000/api/admin/orders/4/status \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <admin_token>" \
  -H "X-Student-Id: 23127300" \
  -d '{"status":"delivered"}'

Phản hồi: 200 OK {"message":"Order status updated"}
```

Lỗi này vi phạm logic nghiệp vụ của order state machine, cho phép "hồi sinh" đơn hàng đã bị hủy. Tác động:
- Trạng thái tracking và báo cáo dễ bị mâu thuẫn.
- Có rủi ro nghiệp vụ khi đơn hàng đã hủy lại được đánh dấu là đã giao.
- Dữ liệu không còn đáng tin cậy cho analytics và dashboard.
