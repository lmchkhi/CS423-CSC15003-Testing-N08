# [BUG][FR-01 Register] Plaintext password disclosed in API response

## Found by Test Case
FR-01 Register + authentication chain security test — kiểm tra dữ liệu nhạy cảm sau khi đăng ký, đăng nhập và đọc hồ sơ

## Requirement liên quan
FR-01 Register / Login / Profile: Mật khẩu không được trả về trong bất kỳ phản hồi API nào. Phản hồi chứa thông tin người dùng chỉ nên có các trường an toàn như `id`, `name`, `email`, `role`, `shipping_address`, `phone`; tuyệt đối không trả `password`.

## Severity / Priority
Critical / P0

## Environment
**Tool**: Postman collection v2.1 / Newman headless
**Collection**: `api/collections/eshop-hw06.postman_collection.json`
**Environment file**: `api/environments/local.postman_environment.json` (`baseUrl = http://localhost:3000`)
**Observed request host**: `http://127.0.0.1:3000` trong collection/Newman logs
**Endpoints involved**: `POST /api/register`, `POST /api/login`, `GET /api/users/me`
**Folder / data / report**: `FR-01 Register`, `api/data/register-cases.json`, `api/newman/fr01-register-report.html`
**Anti-cheat header**: `X-Student-Id: 23127300`
**OS / Hardware / build**: Không được ghi nhận trong Newman artifact nộp; không dùng làm bằng chứng cho bug này.

## Steps to reproduce
1. Gửi `POST /api/register` với `{"name":"User","email":"leaked@test.com","password":"MyPassword123!"}`.
2. Gửi `POST /api/login` với cùng email và mật khẩu.
3. Kiểm tra đối tượng `user` trong phản hồi đăng nhập.
4. Gọi `GET /api/users/me` với token vừa nhận.
5. Kiểm tra phản hồi hồ sơ người dùng.

## Expected result
Các phản hồi không được chứa trường `password`. Login chỉ nên trả token và đối tượng `user` đã được loại bỏ dữ liệu nhạy cảm, ví dụ:

```json
{
  "message": "Login successful",
  "token": "<jwt>",
  "user": {
    "id": 105,
    "name": "User",
    "email": "leaked@test.com",
    "role": "user"
  }
}
```

## Actual result
`/api/login` trả về đối tượng `user` đầy đủ, bao gồm `password` dạng plaintext. `/api/users/me` cũng trả về toàn bộ dòng dữ liệu người dùng, bao gồm `password`. Đây là lỗi lộ dữ liệu nhạy cảm qua phản hồi API.

## Evidence
```bash
curl -X POST http://127.0.0.1:3000/api/register \
  -H "Content-Type: application/json" \
  -H "X-Student-Id: 23127300" \
  -d '{"name":"Test User","email":"leaked@test.com","password":"MyPassword123!"}'

Phản hồi: {"message":"User registered successfully","id":105}

curl -X POST http://127.0.0.1:3000/api/login \
  -H "Content-Type: application/json" \
  -H "X-Student-Id: 23127300" \
  -d '{"email":"leaked@test.com","password":"MyPassword123!"}'

Trích đoạn phản hồi:
{
  "message": "Login successful",
  "token": "<jwt>",
  "user": {
    "id": 105,
    "name": "Test User",
    "email": "leaked@test.com",
    "password": "MyPassword123!",
    "role": "user"
  }
}

curl -X GET http://127.0.0.1:3000/api/users/me \
  -H "Authorization: Bearer <jwt>" \
  -H "X-Student-Id: 23127300"

Trích đoạn phản hồi:
{
  "id": 105,
  "name": "Test User",
  "email": "leaked@test.com",
  "password": "MyPassword123!",
  "role": "user"
}
```

Ghi chú kiểm chứng: bug này được báo như một phát hiện bảo mật dạng black-box vì có thể tái hiện trực tiếp bằng curl/Postman; không cần tham chiếu mã nguồn SUT.
