# [BUG][FR-14 Category CRUD] Duplicate category names allowed

## Found by Test Case
TC-FR14-010 và TC-FR14-045 — kiểm thử trùng tên danh mục phát hiện thiếu ràng buộc duy nhất cho `categories.name`.

## Requirement liên quan
FR-14 Category CRUD: Tên danh mục nên là duy nhất để tránh trùng nhãn trong điều hướng, lọc sản phẩm và quản trị dữ liệu.

## Severity / Priority
Low / P3

## Environment
**Tool**: Postman collection v2.1 / Newman headless
**Collection**: `api/collections/eshop-hw06.postman_collection.json`
**Environment file**: `api/environments/local.postman_environment.json` (`baseUrl = http://localhost:3000`)
**Observed request host**: `http://127.0.0.1:3000` trong collection/Newman logs
**Folder / data / report**: `FR-14 Category CRUD`, `api/data/fr14-post-categories.csv`, `api/newman/fr14-category-report.html`
**Endpoint involved**: `POST /api/categories`
**Anti-cheat header**: `X-Student-Id: 23127300`
**OS / Hardware / build**: Không được ghi nhận trong Newman artifact nộp; không dùng làm bằng chứng cho bug này.

## Steps to reproduce
1. Đăng nhập bằng tài khoản admin và lấy JWT token.
2. Gửi `POST /api/categories` với `{"name":"Điện thoại"}`.
3. Quan sát hệ thống trả `200 OK` và tạo danh mục đầu tiên.
4. Gửi lại `POST /api/categories` với cùng body `{"name":"Điện thoại"}`.
5. Quan sát hệ thống tiếp tục trả `200 OK` và tạo danh mục thứ hai.
6. Gọi `GET /api/categories` để xác nhận có hai danh mục cùng tên.

## Expected result
Khi tên danh mục đã tồn tại, yêu cầu tạo mới phải bị từ chối với `409 Conflict` hoặc `400 Bad Request`, ví dụ:

```json
{
  "error": "Category name already exists"
}
```

## Actual result
SUT cho phép tạo nhiều danh mục có tên giống hệt nhau. Mỗi lần tạo trả một `id` khác nhau, nhưng tên hiển thị trùng nhau.

## Evidence
**Yêu cầu tạo danh mục trùng tên:**

```http
POST /api/categories HTTP/1.1
Host: 127.0.0.1:3000
Content-Type: application/json
Authorization: Bearer <admin_token>
X-Student-Id: 23127300

{
  "name": "Điện thoại"
}
```

**Actual Response:**

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "Category created",
  "id": 2
}
```

**Kiểm chứng bằng `GET /api/categories`:**

```json
[
  {"id": 1, "name": "Điện thoại"},
  {"id": 2, "name": "Điện thoại"}
]
```

Kết quả Newman:
- `TC-FR14-010`: POST tên trùng trả `200`, trong khi mong đợi `409` hoặc `400`.
- `TC-FR14-001`, `TC-FR14-002`: tạo danh mục hợp lệ trả `200`, đúng kỳ vọng.

## Impact
Lỗi này ảnh hưởng chất lượng dữ liệu và trải nghiệm quản trị. Người dùng có thể thấy nhiều nhãn danh mục giống nhau trong menu hoặc bộ lọc, còn admin khó phân biệt danh mục nào đang được dùng. Mức độ không cao vì có thể xóa thủ công, nhưng nên sửa để dữ liệu ổn định hơn.

## Recommended Fix
1. Thêm ràng buộc `UNIQUE` cho `categories.name` ở database.
2. Kiểm tra tên danh mục đã tồn tại trước khi tạo mới.
3. Trả `409 Conflict` khi phát hiện tên trùng.
4. Bổ sung test xác nhận yêu cầu trùng tên bị từ chối.
