# BUG-FR14-003: Duplicate category names allowed (No Uniqueness Constraint)

**Severity:** Low  
**Category:** Data Integrity / Business Logic  
**Status:** Open  
**Date:** 2026-08-20  
**Student ID:** 23127300  

---

## Summary

The API allows creating multiple categories with identical names. No uniqueness constraint exists on the `categories.name` field, violating e-commerce data integrity principles.

---

## Affected Endpoints

- `POST /api/categories`

---

## Expected Behavior (per Business Logic)

Category names should be unique for UI navigation purposes. When attempting to create a duplicate category name, the API should reject the request:

```http
HTTP/1.1 409 Conflict
Content-Type: application/json

{
  "error": "Category name already exists"
}
```

Alternative: `400 Bad Request` with validation error message.

---

## Actual Behavior

Multiple categories with identical names can be created.

### Test Case: TC-FR14-045 (Duplicate category name)

**Setup:**
1. Create category: `POST /api/categories` with `{"name":"Điện thoại"}` → 200 OK, `{id: 1}`
2. Create duplicate: `POST /api/categories` with `{"name":"Điện thoại"}` → 200 OK, `{id: 2}`

**Request (second creation):**
```http
POST /api/categories HTTP/1.1
Host: 127.0.0.1:3000
Content-Type: application/json
Authorization: Bearer <admin_token>
X-Student-Id: 23127300

{
  "name": "Điện thoại"
}
```

**Actual Response:**
```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "Category created",
  "id": 2
}
```

**Expected:** `409 Conflict` or `400 Bad Request`

**Verification:** `GET /api/categories` returns:
```json
[
  {"id": 1, "name": "Điện thoại"},
  {"id": 2, "name": "Điện thoại"}
]
```

## Root Cause (Inferred from Behavior)

The SQLite schema lacks a `UNIQUE` constraint on `categories.name`:

```sql
-- Current schema (inferred)
CREATE TABLE categories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL
);
```

Should be:
```sql
CREATE TABLE categories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE
);
```

Additionally, the application layer does not validate uniqueness before INSERT.

---

## Recommended Fix

1. **Database Level:** Add `UNIQUE` constraint to `categories.name`
   - Requires schema migration
   - Handles race conditions at DB level
   
2. **Application Level:** Check for existing name before INSERT
   ```javascript
   async createCategory(name) {
     const existing = await db.get('SELECT id FROM categories WHERE name = ?', [name]);
     if (existing) {
       throw new ConflictError('Category name already exists');
     }
     // Proceed with INSERT
   }
   ```

3. Return `409 Conflict` when duplicate detected

4. Add test case verifying duplicate rejection
